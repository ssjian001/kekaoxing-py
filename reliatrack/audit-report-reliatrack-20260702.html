📝 总体评估

📋 总体评估

项目概况：ReliaTrack 是可靠性测试全生命周期管理桌面应用（PySide6 6.11 + SQLite/apsw），MVC 变体架构，20 张表 schema v25，32,000 行 Python，394 tests passing。覆盖项目管理、样品追踪、测试计划/任务/结果、Issue 追踪（看板+FA/CAPA）、知识库、待办等模块。

主要风险：最大风险是 ExportWorker 在 QThread 中跨线程访问主线程的 apsw.Connection——导出期间并发操作 DB 有段错误/数据损坏风险。其次是 19 个 src 模块（含 AppController、import_service、全部 views/dialogs）完全无测试覆盖，而最全面的 E2E 测试（539 行）被 pytest collect_ignore 排除在 CI 之外。

亮点：SQL 参数化查询做得扎实（全部使用 ? 占位符）；_safe_kwargs 列名白名单是好的安全实践；外键约束完整（CASCADE/SET NULL 合理搭配）；WAL 模式 + busy_timeout=5000；附件安全（symlink 拒绝 + resolve 校验）；导出路径遍历保护；启动自动备份 + 30 天清理；394 tests 全通过；命名统一 snake_case；无循环依赖。

优先修复：(1) ExportWorker 线程安全 — 子线程创建独立 DB 连接；(2) test_e2e_full.py 纳入 CI；(3) IssueRepo/KnowledgeRepo/TodoRepo list_all 补 _safe_kwargs；(4) AppController 冒烟测试。

总评：B (6.9/10) — 扎实的个人项目，架构清晰、安全基础好、CI/CD 完善。主要扣分在测试覆盖（19 模块零覆盖 + E2E 被排除）和稳定性（跨线程 DB）。这些问题不会阻塞当前使用，但在功能继续扩展时会成为负债。

🔍 详细发现

1. ExportWorker(QThread) 跨线程访问主线程 apsw.Connection

Critical Confirmed
📁 Stability / DataIntegrity 📍 src/handlers/export_handlers.py:25-48 🎯 ExportWorker.run() + connection.py:8-9
问题：ExportWorker 是 QThread 子类，run() 方法调用 handler(ctrl, svc, ...)，其中 ctrl 是 AppController，持有唯一的 apsw.Connection。handler 通过 ctrl.issue_service / ctrl.test_plan_service 访问 DB，最终都走同一个主线程连接。connection.py 文档注释明确声明「apsw.Connection 本身不是线程安全的，禁止跨线程并发写入」。
# connection.py:7-12 — 项目自己的文档 ⚠️ 线程安全说明： - 连接的 *创建* 由 threading.Lock 保护，线程安全。 - 返回的 apsw.Connection 本身 **不是线程安全的**，禁止跨线程并发写入。 # export_handlers.py:25-48 class ExportWorker(QThread): def run(self) -> None: path = self._handler(self._ctrl, self._svc, ...) # ↑ self._ctrl 持有主线程的 apsw.Connection # handler → ctrl.issue_service.list_all() → repos → self._conn # export_handlers.py:314 worker.start() # 在 QThread 中执行 run()
最小修复
# ExportWorker.__init__ 中捕获 db_path，run() 中创建独立连接 def __init__(self, ..., db_path: str): self._db_path = db_path def run(self) -> None: from src.db.connection import get_connection # 子线程创建独立连接（apsw 支持同进程多连接） conn = apsw.Connection(self._db_path) conn.execute("PRAGMA journal_mode=WAL") try: # 用独立 conn 构建 repos/services path = self._handler_with_conn(conn, ...) finally: conn.close()
⏱ 估时： 1 小时  ·  回归测试： 导出期间触发主线程 DB 写入（添加 Issue），验证无崩溃
