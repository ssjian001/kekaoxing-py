## 🔴 严重问题

### 1. Schema 迁移 v11 / v13 不在事务中

**文件**: `src/db/schema.py` → `init_schema()`

v1→v10、v12、v14→v17 的迁移都包裹在 `BEGIN/COMMIT` 事务中，但 v11 和 v13 没有：

```python
# v11 需关闭 FK 约束后重建表，不能在事务内执行 PRAGMA foreign_keys
if current < 11:
    _migrate_v11(conn)   # ← 无事务保护

# v13 修复 v11 丢失的索引 + schema_version 加 UNIQUE 约束
if current < 13:
    _migrate_v13(conn)   # ← 无事务保护
```

`_migrate_v11` 内部包含 `ALTER TABLE RENAME TO` 和 `CREATE TABLE` 操作。虽然 SQLite DDL 本身不可回滚，但如果 Python 进程在迁移中途被 kill（如 OOM），`schema_version` 记录可能与实际 schema 不一致，导致下次启动时迁移逻辑错乱。

**影响**: 极端情况下数据库迁移失败，需要手动修复。

**建议修复**:

```python
# v11: 至少在执行前记录 checkpoint
if current < 11:
    logger.info("Starting migration v11 (non-transactional)...")
    try:
        _migrate_v11(conn)
    except Exception:
        logger.critical("Migration v11 failed — database may be in inconsistent state")
        raise
```

### 2. SoftDeleteCommand 缺少类型守卫

**文件**: `src/services/undo_manager.py` L218-227

`SoftDeleteCommand` 的 `do()` 调用 `repo.soft_delete()`，`undo()` 调用 `repo.restore()`，但这两个方法仅存在于 `IssueRepository`。如果误将其他 Repository（如 `SampleRepository`）传入，会在运行时抛出 `AttributeError`：

```python
class SoftDeleteCommand(Command):
    def do(self) -> None:
        self._repo.soft_delete(self._entity_id)  # 仅 IssueRepository 有
    def undo(self) -> None:
        self._repo.restore(self._entity_id)       # 仅 IssueRepository 有
```

**影响**: 撤销操作失败，用户数据可能丢失。

**建议修复**:

```python
def __init__(self, repo: Any, entity_id: int, entity_name: str = "实体"):
    if not (hasattr(repo, "soft_delete") and hasattr(repo, "restore")):
        raise TypeError(
            f"SoftDeleteCommand requires a repository with soft_delete/restore methods, "
            f"got {type(repo).__name__}"
        )
    ...
```

## 🟠 高严重度

### 3. Qt C++ 层异常静默丢失

**文件**: `main.py` L270-283

```python
sys.excepthook = _global_excepthook  # 只覆盖 Python 异常
```

`sys.excepthook` 只能捕获 Python 层的未处理异常。Qt C++ 事件循环中的错误（段错误、空指针解引用、paint 引擎崩溃）不会经过这个钩子，导致程序静默崩溃，用户看到窗口突然消失，没有任何日志或弹窗。

**影响**: 生产环境崩溃无法追踪。

**建议修复**:

```python
# 在 QApplication 创建后添加：
from PySide6.QtCore import qInstallMessageHandler, QtMsgType

def _qt_message_handler(msg_type, context, message):
    if msg_type in (QtMsgType.QtCriticalMsg, QtMsgType.QtFatalMsg):
        _log.critical("Qt fatal: %s (file=%s, line=%d, func=%s)",
                      message, context.file, context.line, context.function)

qInstallMessageHandler(_qt_message_handler)
```

### 4. 数据库连接无健康检查 / 自动重连

**文件**: `src/db/connection.py` L42-57

```python
def get_connection(db_path: str = "") -> apsw.Connection:
    with _lock:
        if db_path not in _connections:
            ...
            _connections[db_path] = conn
        return _connections[db_path]  # 从不检查连接是否健康
```

如果底层 SQLite 文件被外部进程替换、损坏，或 WAL 文件被误删，`get_connection()` 不会检测到连接已失效，后续 SQL 操作会抛出 `apsw.BusyError` 或 `apsw.CorruptError` 且无恢复机制。

**影响**: 长时间运行后数据库写入失败，用户不知情。

**建议修复**:

```python
# 在关键操作前执行快速完整性检查
try:
    conn.execute("PRAGMA quick_check")
except apsw.Error:
    # 关闭旧连接，重新建立
    _connections.pop(db_path, None)
    conn.close()
    return get_connection(db_path)  # 递归重建
```

### 5. 数据库降级保护缺乏用户引导

**文件**: `src/db/schema.py` → `init_schema()`

```python
if current > SCHEMA_VERSION:
    raise RuntimeError(
        f"数据库 schema 版本 (v{current}) 高于当前代码版本 (v{SCHEMA_VERSION})。"
        f"请升级 ReliaTrack 到最新版本。"
    )
```

如果 `RuntimeError` 发生在 `QApplication` 实例化之前，则是裸异常回溯；如果发生在之后，`_global_excepthook` 会弹出错误弹窗。两种情况用户都不知道如何恢复（备份数据、安装对应版本）。

**影响**: 用户无法启动程序且不知道如何处理。

**建议修复**:
弹窗后给出具体操作指引：备份 `~/.reliatrack/reliatrack.db`、安装匹配版本、或联系管理员。

## 🟡 中等严重度

### 6. 锁文件永久残留

**文件**: `main.py` L309-318

```python
_lock.setStaleLockTime(0)  # 0 = 永不过期
if not _lock.tryLock(100):
    ...  # "ReliaTrack 已在运行中，请勿重复启动。"
```

如果程序崩溃（segfault、kill -9），`~/.reliatrack/.reliatrack.lock` 永久残留，导致重启时弹出「已在运行中」，需要手动删除锁文件。

**建议**: `setStaleLockTime(30000)`（30 秒），或自动检测持有锁的进程是否存活。

### 8. `getrowcount()` 在 INSERT OR IGNORE 场景下不可靠

**文件**: `src/services/holiday_service.py` L79-84

```python
cursor = self._conn.execute(
    "INSERT OR IGNORE INTO holidays (date, name, source) VALUES (?, ?, ?)",
    (d, n, s),
)
if cursor.getrowcount() > 0:  # apsw 版本间行为不一致
    count += 1
```

apsw 的 `getrowcount()` 在 `INSERT OR IGNORE` 冲突无变化时，不同版本可能返回 0 或 `-1`。

**建议**: 先 `SELECT COUNT(*)` 检查，或使用 SQLite 的 `changes()` 函数。

### 9. `closeEvent` 可能误判打开的对话框

**文件**: `main.py` L232-240

```python
open_dialogs = [
    w for w in QApplication.topLevelWidgets()
```

`topLevelWidgets()` 包含已隐藏但未销毁的对话框、`QMenu`、`QToolTip` 等瞬时窗口，可能误报「有窗口正在编辑中」。

### 10. Python 导入路径存在模块阴影风险

**文件**: `main.py` L13-14

```python
_PROJECT_ROOT = os.path.dirname(os.path.abspath(__file__))
sys.path.insert(0, os.path.dirname(_PROJECT_ROOT))  # 插入父目录 xiangmu/kekaoxing-py/
```

父目录 `xiangmu/kekaoxing-py/` 下也有一份 `src/`（含 `db/`、`models/`、`views/` 等），与 `reliatrack/src/` 结构相似但内容不同。当前因为父级 `src/db/` 缺少 `connection.py` 等关键文件，实际导入回退到 `reliatrack/src/`。如果将来有人在父级 `src/` 中添加同名模块，会静默覆盖 `reliatrack/src/` 中的实现。

**建议**: 明确注释说明路径优先级，或删除无用的父级 `src/` 目录。

### 11. `sys.path` 注入与 `PYTHONPATH` 交互未覆盖

**文件**: `main.py` L11-14

```python
_PROJECT_ROOT = os.path.dirname(os.path.abspath(__file__))
if _PROJECT_ROOT not in sys.path:
    sys.path.insert(0, os.path.dirname(_PROJECT_ROOT))
```

检查条件是 `_PROJECT_ROOT not in sys.path`，但注入的是 `os.path.dirname(_PROJECT_ROOT)`。如果用户通过 `PYTHONPATH` 或软链接运行，`_PROJECT_ROOT` 的 `abspath` 展开值可能与 `sys.path` 中已有的路径字符串不完全匹配（尾部斜杠差异），导致重复注入。

## 🔵 低严重度

- **`_pending_entity_types`** (`main.py` L98): 声明为 `set[str]()` 但没有类型注解，依赖推导。
- **`dashboard_view.py`**: QPainter 自定义绘图的 DPI 缩放依赖 `QT_ENABLE_HIGHDPI_SCALING` 环境变量，非整数缩放比（如 125%）下可能出现渲染偏移。
- **`holiday_service.import_holidays`**: 方法名与 Python 关键字 `import` 接近，容易在代码审查时混淆。
